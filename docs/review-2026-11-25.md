# Code review 2026-11-25: performance and reliability

Goal: performance and reliability first. Trigger: after a ride the NAS can't sync and the local web app doesn't open, or only very slowly.
Bluetooth (3 sensors + watch) works since `CONFIG_BT_CTRL_BLE_MAX_ACT=10` (ddeb320) and is the baseline: no BLE timing changes without a device log.

Status legend: **open**, **done** (code, host tests where pure, firmware builds), **verified** (measured on the device), **to try** (on the device, needs a ride), **held** (needs a log or a decision).

## A. After a ride: NAS can't sync, web app slow

| # | Finding | Proposal | Status |
|---|---|---|---|
| A1 | Wi-Fi comes back only when the ride summary is dismissed ("Done"); a rider who walks away leaves it off, so the NAS sees the device as off and trainer.local doesn't answer (`app.c` web_on needs `RIDE_IDLE`, only `ACT_DISMISS` gets there). | Start Wi-Fi as soon as the ride is saved, while the summary shows. | to try |
| A2 | BLE scans 30 ms of every 100 ms for as long as any role is missing (HR strap off, Ride asleep: the normal state after a ride): ~30 % of the shared radio taken from Wi-Fi while idle. | Lower scan duty while idle with Wi-Fi on. Needs a log and a 4-link test. | held |
| A3 | `LWIP_TCP_SND_BUF_DEFAULT` / `TCP_WND_DEFAULT` 5760 B: throughput ≈ 5.7 KB / RTT, ~60–110 KB/s at coex RTTs (web app 1.2 MB ≈ 10–20 s). | 16 KB send buffer, 11.5 KB window, recvmbox 12 (lwIP memory is in PSRAM). | verified: 12–25 KB/s → ~250 KB/s, DuckDB 7.6 MB in 30 s (timed out at 60 s before), app.js 0.4–2.7 s → 0.16 s |
| A4 | One request at a time on the device; right after a ride the NAS pulls CSV + FIT + summary + bests and the browser waits behind it. | NAS pulls small/needed files first (summary, bests, CSV), FIT files last. | done (NAS tests) |
| A5 | `/api/rides` and `/api/workouts`: one `stat()` per file (FAT searches the folder each time: O(n²), ~tens of seconds at ~700 files) and one HTTP chunk per entry. | Read size/date from FatFs `f_readdir` directly (`bsp_sd_list`), send JSON in 4 KB chunks. | verified: same JSON and times as `stat()` (ETag matches), 0.2–0.4 s for 34 files |
| A6 | DHCP takes 5–25 s at -75…-80 dBm; the access-point fallback at 15 s starts AP + STA + BLE (7–20 s per request) in many joins. | Fallback after 30 s. Held: the Bluetooth scan is paused while joining, so sensors would connect up to 30 s later at start-up. | held |

## B. Performance
